### Pemisahan Storage Cloudflare (Pages + R2)
Sesuai arahan pemilik, situs publik kini menerapkan prinsip seleksi ketat dan efisiensi penyimpanan:
1. **Hanya makhluk lengkap bergambar:** Dari seluruh entri, hanya makhluk berstatus `lengkap-bergambar` (125 makhluk) yang masuk ke bundel publik `dist/` saat build dengan `MYTHICS_PUBLISH=complete`.
2. **Pemisahan Media ke R2:** Gambar makhluk dipisahkan ke `dist-media/art/` (112 file) dan diakses via URL `/media/art/*`.
3. **Pages Functions (`functions/media/[[path]].js`):** Menghubungkan binding R2 `MEDIA` ke endpoint internal `/media/` dengan edge caching Cloudflare (`Cache-Control: public, max-age=86400, stale-while-revalidate=604800`) dan Cache API, menjaga CSP tetap `'self'`.
4. **Sinkronisasi R2 Efisien (`scripts/upload-media.mjs`):** Memeriksa SHA256 melalui `_manifest.json` di bucket `mythics-media`, hanya mengunggah file gambar yang baru atau berubah.
5. **Aset UI Lokal:** Gambar antarmuka yang dirujuk UI (seperti Barong) tetap disajikan langsung dari Pages (`dist/assets/art/`) tanpa ketergantungan storage luar.
6. **Workflow Deploy (`.github/workflows/deploy.yml`):** Membangun situs publik dengan `MYTHICS_PUBLISH=complete MEDIA_BASE=/media`, membuat bucket R2 bila belum ada, menjalankan `upload-media.mjs`, lalu mempublikasikan ke Cloudflare Pages.
